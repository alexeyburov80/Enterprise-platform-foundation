# Установка без доступа в интернет (air-gap)

Классическая схема: **всё, что требует сети, собирается один раз на машине с
интернетом, переносится офлайн-носителем (USB/rsync/scp) на целевой сервер.**
Дальше на целевом сервере интернет не нужен вообще, включая рестарты/пересборку.

Подробности механики (что именно внутри bundle, почему без cert-manager,
пошаговый ручной запуск для отладки) — в
[`infra/airgap/README.md`](../infra/airgap/README.md). Этот файл — краткая
версия под тем же названием, что и остальные `docs/*`, для единообразия навигации.

## Шаг 1 — на машине с интернетом

```bash
cd infra/airgap
./scripts/00-fetch-bundle.sh
```

Соберёт `airgap-bundle.tar.gz` рядом со скриптом. Внутри — k3s, kubectl, helm,
crane (статические бинарники), Helm-чарты Kong и kube-prometheus-stack,
манифесты RabbitMQ-операторов, все нужные образы контейнеров (включая
`mes-stub` и сам образ локального registry для профилей standard/ha) — все
версии зафиксированы в `release/manifest.yaml`, без единого `latest`.

## Шаг 2 — перенос

Любым офлайн-способом (USB, rsync через промежуточный узел, scp туда, куда
есть доступ и оттуда на изолированный сервер и т.п.) — вне скоупа этого
репозитория, зависит от вашей инфраструктуры/регламента.

## Шаг 3 — на целевом сервере

```bash
sudo ./bootstrap.sh --profile single --offline --bundle infra/airgap/airgap-bundle.tar.gz
```

Замените `single` на `standard`/`ha`, если разворачиваете на нескольких узлах —
см. ниже про `registry.local`.

## Проверка "действительно ли сеть не используется"

См. [`infra/airgap/TRANSFER-CHECKLIST.md`](../infra/airgap/TRANSFER-CHECKLIST.md) —
контрольные суммы бандла, порядок действий, и как проверить это по-настоящему
(отключенный интерфейс/`iptables` blackhole), а не поверить на слово.

## Несколько узлов офлайн (`--profile standard` / `--profile ha`)

`bootstrap.sh` в offline-режиме для этих двух профилей дополнительно запускает
`infra/airgap/scripts/25-start-registry.sh` — поднимает локальный registry на
узле, где распакован bundle, пушит туда все образы, настраивает k3s
(`/etc/rancher/k3s/registries.yaml`, wildcard-mirror) так, чтобы образы
резолвились через него, а не напрямую из интернета.

**Это решает** саму возможность физически получить образы на нескольких узлах
офлайн. **Это НЕ решает** (пока делается вручную):
- присоединение дополнительных control-plane/worker узлов к кластеру
  (`k3s agent --server ... --token ...`) — по официальной документации k3s;
- перед запуском k3s/k3s-agent на КАЖДОМ дополнительном узле нужно вручную
  создать на нём тот же `/etc/rancher/k3s/registries.yaml` (готовое содержимое
  печатает `25-start-registry.sh` в конце) — иначе узел попытается тянуть
  образы из интернета и упадёт;
- открытие порта registry (по умолчанию 5000, см. `release/manifest.yaml` →
  `registry.port`) между узлами на уровне firewall/security group.

Подробнее — раздел "Несколько узлов офлайн" в
[`infra/airgap/README.md`](../infra/airgap/README.md#несколько-узлов-офлайн-профили-standardha).

## Апгрейд офлайн-кластера

См. [UPGRADE.md](./UPGRADE.md) — офлайн-апгрейд сейчас means "собрать новый
bundle с новыми версиями в `release/manifest.yaml` и повторить перенос", без
autonomous delta-апгрейда. Это осознанное текущее ограничение, не забытый пункт.

## Если что-то не так

`./scripts/diagnose.sh` (запускается и офлайн — не обращается в интернет, только
к `kubectl`) и [TROUBLESHOOTING.md](./TROUBLESHOOTING.md).
